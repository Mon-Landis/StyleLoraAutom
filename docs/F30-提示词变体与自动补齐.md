## 2. 模块 A：模型、迁移与字段状态

职责：定义内容与内部状态边界、验证变体、升级组快照；依赖现有 immutable、PromptError/Issue、GroupStore。

### 2.1 数据类型

```python
BaseField = Literal['tag', 'expand_nl', 'nl']
JsonObject = dict[str, Any]
# 以下为 Entry 新增字段；持久化时 Mapping 编码为 JSON object。
variants: Mapping[str, str]                         # 默认 {}
generated: GeneratedFields                         # 默认全部 false / {}
pending: Mapping[BaseField, PendingField]            # 默认 {}
edit_versions: FieldVersions                       # 默认全部 0 / {}
# GeneratedFields = {tag:bool, expand_nl:bool, nl:bool, variants:Mapping[str,bool]}
# FieldVersions = {tag:int, expand_nl:int, nl:int, variants:Mapping[str,int]}
# PendingField = {state:Literal['pending'], task_id:str, attempt:int,
#                 edit_version:int, input_digest:str}
```

- `tag` 按整个数组标记；expand_nl、nl、每个 variant 各自标记。generated 表示“模型生成且尚未经用户编辑”，不是来源审计。
- variants 每 key 对应一个字符串；保留文本首尾空白和段落，CRLF/CR 统一 LF；判空使用 `text.strip()`。
- key 去首尾空白、区分大小写，1–128 字符，拒绝控制字符；规范化后重名报逐字段错误；不按点号拆 key。
- 决定每 Entry 最多 64 个 key、每值最多 16000 字符，继续执行整体导入大小限制；拒绝非字符串值。
- 保持 F27 的三个基础内容字段至少一项非空；仅有变体不能创建词条。添加空 key 是对有效 Entry 的编辑。
- 生成标记、pending、edit_versions、completion、preview 均不是 EntryDraft 内容字段；客户端不得伪造。
- `completion.state='pending'` 继续表示“有缺口”；`Entry.pending[field]` 才表示“已被任务占用”，两者不可混用。

### 2.2 组与首选项

- Group/GroupSummary 新增 `auto_complete: bool`。
- 产品设置新增 `prompt_auto_complete_default: bool = True`；GET/PATCH /api/settings 暴露，严格校验 bool。
- 新建组未显式传开关时，在创建事务内读取该偏好；偏好变化不回写已有组。
- 导入新组、复制整组继承源 auto_complete；源为旧格式且缺字段时取当前偏好，并在预览冻结。
- 追加条目到已有组不改变目标组开关；单条复制不携带组开关。复制整组走导出内容→导入流程。
- 用户可通过组设置修改开关。关闭只阻止后续自动发布，不取消已受理任务；手动补全仍可用。
- 未来的变体自动追加默认值、快捷键等偏好只规划，本期不加入可操作设置。

### 2.3 pending 存放决定与一致性

决定：字段锁持久化在所属组 JSON 的 Entry.pending；任务记录保存对应冻结输入与 attempt。
理由：锁、人工编辑版本、生成结果和收据能在同一个 GroupStore.mutate 原子提交；前端内存锁不能跨刷新、多窗口和重启去重。
不另建锁文件，不以 completion.state 推断所有字段被占用；UI 显示生成中但仍允许人工编辑。
edit_versions 在用户提交该字段时递增，即使规范化后值相同；避免“填入再清空”后旧响应重新填入。
用户编辑不提前释放在途锁；结果/终止清理只能删除 task_id+attempt 匹配的锁，不能删除新任务锁。

### 2.4 迁移与公开接口

```python
def validate_entry(raw: JsonObject, *, catalog: Any = None,
                   allow_id: bool = True) -> Entry: ...
def decode_group(raw: JsonObject) -> Group: ...
def migrate_v3(raw: JsonObject, *, auto_complete_default: bool = True) -> Group: ...
def migrate_v2(raw: JsonObject) -> Group: ...  # 保留旧入口，输出当前版本
def migrate_group(raw: JsonObject, *, auto_complete_default: bool = True) -> Group: ...
def content(entry: Entry) -> JsonObject: ...  # 内容含 variants，不含内部状态
```

- 仅 prompts 组存储升至 `schema_version=4`；features、project.db 和旧字典类型版本不变。
- v3→v4 保留 ID、scope、preview、内容、收据；新增 variants={}、generated 全 false、pending={}、edit_versions 初始值，auto_complete 取迁移时偏好。
- v1/v2 复用既有字段映射与稳定 UUIDv5，再补 v4 字段；整体迁移只增加一次 revision。
- 纯迁移不调用 LLM。旧 queued/running 无字段锁的任务在恢复阶段置 paused，不猜测锁、不重放未知调用。
- 仓储锁内备份原始字节并校验，再原子写 v4 及 migration:v4 收据；备份沿用源版本命名。v4 重读不再备份或增 revision。
- 墓碑独立升级外壳，不调用 Entry 解码；保留 _deleted 和收据。未知高版本拒绝写入。
- 同步 `prompts/dictionaries.py` 的新组只读适配/禁止旧入口写入判定，以及 `prompts/validation.py` 相关版本白名单，避免 v4 被当旧字典覆盖。
- 错误：schema:invalid（含字段路径）、newer_version、storage:corrupt_snapshot/io_error；失败保留原文件。
- 幂等：纯迁移固定输入固定输出；持久迁移以版本和收据去重。最小测试：v3 重复加载、v1/v2 ID 不漂移、备份失败不覆盖、墓碑不复活。

## 3. 模块 B：编辑与设置 API

职责：部分编辑、逐字段清标记和版本递增、组开关/偏好；依赖模块 A 和现有 CAS/幂等收据。
涉及 `runtime/prompt_groups.py`、`runtime/product.py`、`api/routes/prompt_groups.py`。

```python
def PromptGroups.create(self, value: JsonObject, key: str) -> JsonObject: ...
def PromptGroups.edit(self, ref: GroupRef, patch: JsonObject, revision: int,
                      key: str, entry_id: str | None = None,
                      action: str = 'patch') -> JsonObject: ...
def apply_user_patch(entry: Entry, patch: JsonObject) -> Entry: ...
def Product.update_safety(self, patch: JsonObject, expected: int,
                         request_key: str) -> JsonObject: ...
```

所有路由前缀 `/api`；G/E 沿用 F27，query 携带 scope/project_token；写请求沿用 If-Match、Idempotency-Key。

| 请求 | 响应与语义 |
|---|---|
| POST /prompt-groups `{name,scope,nsfw?,auto_complete?}` | 201 GroupSummary，含 auto_complete/schema_version=4 |
| PATCH G `{name?,nsfw?,auto_complete?}` | 200 GroupSummary + revision/version/ETag |
| POST G/entries `EntryDraft` | 201 Entry；人工创建各生成标记为 false |
| PATCH E `{tag?,expand_nl?,nl?,disable?,aspect?,variants?}` | 200 完整 Entry + revision/version/ETag/nsfw |
| PATCH /settings `{prompt_auto_complete_default?:bool}` | 200 设置快照 + revision/version/ETag |

PATCH 中 `variants: {key: string | null}` 为按 key 合并：字符串新增/替换，null 删除，未提供 key 保留；`variants:{}` 无操作。
POST/导入的 variants 是完整 `Record<string,string>`，不接受 null；两者类型不可复用。
示例：`{"nl":"人工描述","variants":{"short":"第一行\n第二行","old":null}}`。
响应保留其他内容；generated.nl=false、generated.variants.short=false，old 的内容/标记移除；保留 old 的内部版本计数用于防止删除重建的旧结果写回。
用户 PATCH 提及的文本字段一律清生成标记并递增版本；同值、空白改动、删除后撤回均算编辑。仅改 disable/aspect 不清文本标记。
前端只提交实际触及字段，禁止把整个 Entry 当 PATCH；编辑失败保留草稿。确定性 expand_nl→nl 推导沿用 F27，推导字段继承其源的生成属性；人工修改源导致的推导不标模型生成。
generated/pending/edit_versions 在响应只读；提交这些字段报 422。不得通过重建 Entry 丢失未编辑字段锁或标记。
错误：422 schema:invalid；404 entry:not_found；412 dictionary/settings:revision_conflict；409 dictionary:request_key_conflict。
幂等：同 key/同请求重放原收据，不再次递增字段版本；同 key 不同请求拒绝。
最小测试：编辑一个 variant 不影响另一个；同值编辑清标记；412 不丢草稿；重放不二次清锁或增版本。

## 4. 模块 C：导入导出与 TXT

职责：无损携带变体与组开关；依赖模块 A/B、现有预览冻结/确认提交管线。
涉及 `prompts/group_exchange.py`、新增 `prompts/group_txt.py`、`api/routes/prompt_groups.py`；旧 `prompts/exchange.py` 仅作兼容入口参考。

```python
def encode_group_txt(metadata: JsonObject, entries: Sequence[Entry]) -> bytes: ...
def decode_group_txt(data: bytes) -> JsonObject: ...  # {group_metadata,prompts}
def GroupExchange.preview_import(self, data: bytes | Path,
    options: JsonObject | None = None, request_key: str | None = None) -> JsonObject: ...
def GroupExchange.commit_import(self, preview_id: str, signature: str,
    expected_revision: int, request_key: str, ref: GroupRef | None = None) -> JsonObject: ...
def GroupExchange.export_group(self, ref: GroupRef,
    format: Literal['json','txt','folder','zip'] = 'json') -> bytes | JsonObject: ...
```

- JSON/组包条目增加 variants，metadata 增 auto_complete；交换 `format_version=1` 保持不变（可选字段扩展）。旧应用可能拒绝新字段，明确提示升级，不自动删变体降级。
- 导出所有空 key、禁用条目；不导出 generated/pending/edit_versions/completion/_operations。导入默认无生成标记，不从文本推断来源；外部内部状态字段按未知字段拒绝。
- TXT 决定使用显式版本头的行格式，避免旧逗号文本无法区分变体、反斜杠和换行：第一行固定 `# stylelora-prompts-txt v1`；第二行为单行 JSON `{group_metadata:{...}}`；之后每个物理行一个完整 EntryDraft JSON。
- UTF-8，接受 BOM 与 CRLF 文件行结束；导出无 BOM、LF。字符串按 JSON 标准转义：真实 LF→`\n`、反斜杠→`\\`、双引号→`\"`、TAB→`\t`；内容先统一 CRLF/CR 为 LF。
- 示例值：真实两行 A/B 编码为 `"A\nB"`；字面量反斜杠+n 编码为 `"A\\nB"`，读回必须可区分。只做一次 JSON 解码，不再执行旧 _unescape_nl 或 sentinel 替换。
- 有版本头但版本未知或行损坏，不回退为普通文本；重复 key（包括 JSON 对象重复键）、未知字段、类型错误逐行报告原物理行号。
- 无版本头的旧 TXT 通过旧行解析适配为 tag/expand_nl/nl，variants={}；预览警告其无法恢复组元数据，不能把普通文本猜成新格式。
- `POST /prompt-imports/preview` multipart 的 options.format 增 txt；`GET G/export?format=txt` 返回 text/plain; charset=utf-8 附件。单条复制仍使用 JSON。
- TXT 与 JSON 共用 10 MiB/10000 条限制、有效行预览和部分跳过规则；非法头/metadata 阻止全组导入。
- 幂等：预览冻结 auto_complete/ID/摘要，确认重试沿用收据；导出冻结单一 revision。
- 错误沿用 import:encoding/limit/empty、schema:invalid、preview:expired；最小测试：多行与字面量 `\n` 往返、空 key 值、Unicode、重复键、旧 TXT、组开关继承、内部状态不泄漏。

## 5. 模块 D：自动补齐与生成写回

职责：字段选择/占用、任务发布、逐字段条件写回、锁恢复及新条目标记；依赖 A/B、GroupStore、现有统一任务中心和 LLM/skill 适配器。
涉及 `runtime/prompt_completion.py`、`runtime/prompt_generation.py`、`runtime/lifecycle.py`、`api/routes/tasks.py`。

```python
async def PromptCompletion.enqueue(self, ref: GroupRef,
    entry_ids: Sequence[str] | None, base_revision: int, request_key: str,
    *, trigger: Literal['manual','auto_leave'] = 'manual') -> JsonObject: ...

def PromptCompletion.apply_result(self, record: JsonObject,

def PromptCompletion.release_pending(self, record: JsonObject,

```

### 5.1 发布协议

`POST /api/tasks` + Idempotency-Key：
`{type:"prompt_completion",ref,base_revision,trigger:"auto_leave"}`；省略 entry_ids 表示全组，包括尚未分页加载的条目。
手动入口沿用 entry_ids 和默认 trigger=manual；自动入口不允许带 entry_ids，以免只补当前页。
响应固定 202 TaskView（统一中心 task_id，kind=prompt，resources.kind=prompt_completion）。
组开关关闭、无缺口或全部占用时，返回 status=done 的空任务，不调用 LLM、不改组 revision；相同幂等键重放同任务。
GET /tasks/{id} 的 reports 新增 `applied_fields:BaseField[]`、`discarded_fields:BaseField[]`，保留现有 error_code/warnings。
锁占用引起的组 revision 变化经重新 GET G/entries 获取；客户端不能继续使用发布前 ETag 编辑。

1. 首先按 request_key+请求摘要重放已有记录，再检查 base_revision；同键不同摘要返回 409。
2. 锁内重新加载组；auto_leave 要求 auto_complete=true，跳过 disable；manual 单条仍可显式补全禁用项。
3. 缺口按当前规范内容推导，减去 pending.keys()；不依赖旧 completion.missing 快照，不包含 variants/aspect。
4. 有候选才检查 skill/LLM 就绪。冻结每项基础内容、缺字段、edit_versions、输入摘要与 attempt。
5. 先持久化 status=preparing 的任务记录（内部发布阶段），再通过一次组 mutate 占用字段并写发布收据，随后保存 queued 状态，最后启动 worker；这些步骤在现有仓储锁下完成且不得跨 await 持锁。
6. 不同请求键竞争同字段时，后到者重新检查锁并排除；CAS 冲突返回 412，不开始模型调用。选中字段必须与成功占用字段完全一致。
7. preparing 不向 worker 发布；中断后依据组发布收据恢复登记或标失败并释放，绝不盲目再调用模型。

### 5.2 写回及锁释放

- 在仓储锁内先查 task/attempt/entry 的结果收据，再加载最新 Entry；组 revision 改变不直接拒绝整批。
- 对每个冻结缺字段分别检查：pending 所属 task_id+attempt 相符、当前值仍空、edit_version 等于冻结值。
- 用户已填非空：丢弃该字段结果，记录 discarded_fields，保留人工值和清除后的标记；即使用户又清空，版本变化也丢弃旧结果。
- 其他原来非空的基础源字段若被编辑，旧推理依据失效：剩余候选报 completion:stale，不写回；仅 variants/disable/aspect 或其他条目变化不使基础补齐整体失效。
- 可写字段单独验证模型类型/长度/tag，再合并到当前内容；只给实际写入的非空模型字段置 generated=true。模型多返回的非目标字段只记 warnings。
- 某目标字段人工填写不阻止其他仍空且版本未变的目标写回；不得再使用现有整条 content_digest 相等作为唯一条件。
- 在同一 mutate 中保存内容、generated、缺口状态、释放本 attempt 的锁、结果摘要收据；重复回调直接返回收据，不再次覆盖。
- 字段仍缺失为 completion:incomplete；条目已删除报 entry:not_found，组不存在/项目关闭不重建对象；丢弃人工字段可记 warning，不把有效人工内容判错。
- 成功、部分失败、模型异常、取消、暂停、关闭项目都调用归属匹配的锁释放；晚到响应无有效锁即丢弃。
- 重启/重开项目先 reconcile，再接受自动发布：终态任务残锁清除；孤儿锁清除并报告；未知在途调用转 paused 且禁自动重放。
- 决定 failed/paused/canceled 条目不由反复离开自动重试，以遵循既有“未知结果不自动重放”规则；显式手动重试或用户编辑后重新产生缺口可重新入队，生成新 attempt。
- 模型返回后保存失败：保留旧内容，任务报告 storage:io_error；恢复只根据已有收据补报告/清锁，不再次调用 LLM。

### 5.3 prompt_generation 新词条

`PromptGeneration.apply_result` 验证批次后，在原有 generation-append 原子操作中给模型提供的非空 tag/expand_nl/nl 标记 generated=true；确定性派生字段继承源标记。
空字段不标记，variants 默认空；未来生成变体时复用相同逐 key 标记合同，本期不扩大模型输出 schema。
幂等仍按 task_id+batch 收据，追加内容与标记一起提交；reconcile 只恢复报告。
错误沿用 completion:unavailable/stale/incomplete、llm:outcome_unknown 和仓储错误；不记录密钥或完整模型输出到用户错误。
最小测试：fake LLM 延迟返回期间人工填写、不同键并发发布、取消后晚到结果、发布各阶段崩溃恢复、generation 批次重放仅追加一次且标记完整。

### 6.1 客户端类型与接口

修改 `frontend/src/api/promptGroupTypes.ts`、`promptGroups.ts` 及现有设置客户端类型；保留既有字段。

```typescript
type BaseField = 'tag' | 'expand_nl' | 'nl';
type PromptView = 'default' | 'nl' | 'variants';
type GeneratedFields = Record<BaseField, boolean> & { variants: Record<string, boolean> };
type PendingField = { state: 'pending'; task_id: string; attempt: number;
  edit_version: number; input_digest: string };
type EntryPatch = Partial<Pick<EntryDraft, 'tag'|'expand_nl'|'nl'|'disable'|'aspect'>>
  & { variants?: Record<string, string | null> };
// EntryDraft 新增 variants?:Record<string,string>；读取 Entry 的 variants 必有值。
// Entry 新增 generated:GeneratedFields、pending:Partial<Record<BaseField,PendingField>>，
// edit_versions:Record<BaseField,number>&{variants:Record<string,number>}；内部字段只读。
// GroupSummary/GroupView 新增 auto_complete:boolean；GroupCreateBody 增 auto_complete?:boolean。
// ProductSettings 增 prompt_auto_complete_default:boolean。
patchEntry(ref:GroupRef, id:string, body:EntryPatch, etag:string, key?:string):Promise<Versioned<Entry>>;
patchGroup(ref:GroupRef, body:{name?:string;nsfw?:boolean;auto_complete?:boolean},
  etag:string, key?:string):Promise<Versioned<GroupView>>;
enqueueCompletion(ref:GroupRef, ids:string[]|undefined, revision:number,
  key?:string, trigger?:'manual'|'auto_leave'):Promise<TaskView>;
patchSettings(body:{prompt_auto_complete_default?:boolean}, etag:string,
  key?:string):Promise<Versioned<ProductSettings>>;
exportGroupTxt(ref:GroupRef):Promise<Blob>;
previewImportFile(file:File, options:ImportOptions & {format:'txt'}, key?:string):Promise<ImportPreviewV3>;
```

AutoCompletionContext 提供当前 ref、auto_complete、`flushEdits:()=>Promise<void>`、`refreshRevision:()=>Promise<number>` 和 `notifyError:(e:unknown)=>void`；TaskView 复用统一任务类型。
previewImport 的 metadata 类型增 auto_complete；复制整组必须保留导出 metadata，不能只复制 prompts 数组。

### 6.2 离开与错误处理

1. 捕获离开前的 GroupRef；切换其他组、应用内离开提示词页都先 flushEdits，再读取最新 revision，发布 auto_leave，最后完成导航。切视图/同组分页不触发。
2. 页面级 coordinator 位于导航卸载之外；同一次导航共用 promise 和幂等键，React StrictMode effect 重放不得产生新请求；不依赖组件 cleanup 发布。
3. 自动入口不传当前页 ID。发布后使旧组查询失效；返回旧组时重新拉取状态，避免用旧 ETag 保存。
4. 网络结果不明重试使用原请求键；412 重读组/开关后最多重试一次，新 revision 对应新键；服务端字段锁负责不同导航/窗口间去重。
5. 保存失败阻止离开并展示可恢复草稿；补齐失败显示全局通知但允许导航，不能静默标成功。completion:unavailable 提示配置 skill/LLM，不循环重试。
6. 浏览器刷新/关闭使用离开协调器尝试 keepalive 发布（无未保存草稿时）；有未保存草稿启用现有 beforeunload 提醒。硬关闭无法保证 HTTP 送达，不把 visibilitychange 当离开事件。
7. 幂等：同一离开动作一次发布，所有成功响应按原 ref 更新缓存，不把旧组结果灌入新组。

最小测试：三视图切换、空 key 编辑、多行与标记、StrictMode 导航去重、保存后发布顺序、412 单次刷新、未加载页由后端补齐。
