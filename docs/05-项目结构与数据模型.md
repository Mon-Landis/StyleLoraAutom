## 1. 产品定位与范围

### 1.1 定位

- 主体是**数据集清洗编辑器**，原 TagCleaner 的能力整体并入。
- NAI 自动生成只是**数据源的一种选项**，与外部图片导入、其它生图接口平行。
- 最终产物：训练 Anima 画风 LoRA 用的「图片 + 同名 txt」。

### 1.2 范围

| 类别 | 内容 |
|---|---|
| 本版实现 | 项目管理、外部导入、NAI 数据源、提示词生产、清洗工作台（WD / LLM 视觉 / 批量规则 / 审图）、默认导出（图片 + 同名 txt） |
| 仅预留 | 其它生图接口数据源、角色 LoRA、训练器集成、`clean` / `clean_nsfw` 角色、Danbooru `rating` 字段、其它导出格式、NAI 账号状态展示 |
| 已否决 | 前端：Svelte、Gradio / Streamlit、Flutter（Tauri 留作后期桌面外壳） |

## 2. 分层模型

| 层 | 职责 | 数据位置 |
|---|---|---|
| 项目层 | 项目名、画风触发词（Anima LoRA 用） | `project.json` |
| 提示词生产层 | 特征字典组合 → 可选 LLM 优化 → 存入提示词词典 | 词典在产品层；项目只记 `dict_refs` |
| 数据源层 | 外部导入 / NAI 生成 / 其它接口（预留） | `sources`、`source_items` |
| 图集层 | 图片 + 分层标注（原始提示词解析 / WD tagger / LLM 视觉反推 / 手工 / 规则） | `images`、`annotations`、`images/` |
| 导出层 | 可配置导出方案，默认「图片 + 同名 txt」，其余只做扩展规划 | `export_schemes`、`exports/` |
| 产品层（项目外） | LLM 端点与密钥、模型角色分配、MCP 配置、标签翻译库、WD tagger 模型、字典库 | 用户级目录，见第 4 章 |

层间依赖规则：

- 依赖方向：导出层 → 图集层 → 数据源层；提示词生产层仅为 NAI 等生成类数据源提供输入。
- 离开数据源层后，图片来源不强制可追溯（`images.source_id` 可空）。
- 项目层与产品层之间只通过「角色名」「字典名 + 哈希」两种引用耦合，不存配置内容。

## 3. 项目目录结构与规则

项目 = 一个目录：

```
MyStyle.slproj/
├── project.json     # 格式版本、名称、触发词、创建时间
├── project.db       # SQLite，全部业务数据
├── images/          # 以 image_id 命名
├── cache/           # 缩略图，可重建可删
└── exports/
```

| 目录/文件 | 内容 | 可删 |
|---|---|---|
| `project.json` | `format_version`、`name`、`trigger_word`、`created_at` | 否 |
| `project.db` | 全部业务数据 | 否 |
| `images/` | 图片文件，文件名 = `image_id` + 原扩展名 [待确认：扩展名是否保留] | 否 |
| `cache/` | 缩略图等派生文件 | 是，可重建 |
| `exports/` | 导出产物，按方案与时间分子目录 [待确认] | 是，可重新导出 |

规则：

| # | 规则 |
|---|---|
| 1 | 项目内只用相对路径，整个目录可搬迁、可压缩分发 |
| 2 | 项目**不存**产品级配置：只存角色名（如 `vision`），不存端点地址和密钥 |
| 3 | 每条执行结果记录**实际使用的模型名和参数**，溯源不依赖产品配置还原 |
| 4 | `project.json` 带 `format_version`，用于后续迁移；版本高于当前程序支持时拒绝打开 [待确认] |
| 5 | 外部导入的图片**复制进项目** `images/`，不引用原位置 |
| 6 | 项目不存字典内容，只存字典名 + 内容哈希（见 4.4、5.8） |

## 4. 产品层配置

产品层配置存放在项目外的用户级目录 [待确认：具体路径，非密钥部分暂定 `%APPDATA%` 下]，所有项目共享。

### 4.1 内容总览

| 配置项 | 说明 |
|---|---|
| LLM 端点与密钥 | 见 4.2、4.3 |
| 模型角色分配 | 见 4.2 |
| MCP 配置 | NAI Launcher MCP 的发现与 token（协议见 docs/02） |
| NAI 账户配置 | 预留 |
| 标签翻译库 | tag → 中文翻译；同时用于判定「能否在标签库查到」（见 8.2） |
| NSFW 关键词表 | 格式 `tag<TAB>等级`（见第 9 章） |
| WD tagger 模型 | 本地可选组件，从源下载不打包（见 8.7） |
| 字典库 | 特征字典、提示词词典（见 4.4） |

### 4.2 LLM 配置

端点列表，每个端点包含：

| 属性 | 说明 |
|---|---|
| 地址 | 基础 URL |
| 协议格式 | 独立配置：`openai_chat` / `openai_responses` / `anthropic_messages`。适配器插件化，预留扩展 |
| 令牌列表 | 可配多个，轮换使用 |
| 模型列表 | 可选多个；每个模型带「支持图像」标记 |

行为：

| 项 | 设计 |
|---|---|
| 多令牌轮换 | 请求在可用令牌间轮换 |
| 限流处理 | 收到 429 切换到下一个令牌；全部令牌受限时退避重试（见 8.5） |
| 「支持图像」标记 | 手动标记；提供**测试按钮**实测；可读端点 `/models` 时自动标记，读不到可手填 |

模型角色：

| 角色 | 用途 | 状态 | 空值行为 |
|---|---|---|---|
| `prompt` | 提示词生产 | 本版实现 | 跳过 LLM 优化 |
| `prompt_nsfw` | NSFW 提示词生产 | 本版实现 | **默认空 = NSFW 提示词不做 LLM 清洗** |
| `vision` | 视觉反推，需多模态 | 本版实现 | 视觉执行器不可用 |
| `vision_nsfw` | NSFW 视觉反推 | 本版实现 | 跳过该 LLM 步骤，保留原值（见第 9 章） |
| `rating` | 分级，可选 | 本版实现 | 不使用分级模型 |
| `clean` | 数据清洗 | **预留，不实现** | - |
| `clean_nsfw` | NSFW 数据清洗 | **预留，不实现** | - |

项目侧只保存角色名（见第 3 章规则 2）。

### 4.3 密钥存储

- 沿用 TagCleaner 方案：`%LOCALAPPDATA%` 下 DPAPI 加密的 `secrets.json`。
- 环境变量优先于 `secrets.json`。
- 本地 API 不返回明文密钥。
- 密钥不进入项目目录，因此项目可安全分发。

### 4.4 字典库

字典**只存在产品层**。

| 字典类型 | 说明 |
|---|---|
| 特征字典 | 提示词生产的原料，可导入；也可由「特征生成源」（如 NAI Launcher 的随机提示词词库）现场生成 |
| 提示词词典 | 自定义，保存可直接用于出图的内容段提示词；可导入导出，LLM 优化结果可追加条目 |

项目与字典的关系：

- 项目不存字典内容，只在 `dict_refs` 记录「用过的字典名 + 内容哈希」（见 5.8）。
- 打开项目时逐条比对当前字典哈希；不符则提示「字典已变更」。
- 字典缺失时同样提示，不阻止打开 [待确认]。

## 5. project.db 表设计

### 5.1 总览与约定

| 表 | 用途 | 字段数 |
|---|---|---|
| `sources` | 数据源 | 12 |
| `source_items` | 生成索引，核查与断点续跑 | 9 |
| `images` | 图片登记 | 11 |
| `annotations` | 分层标注 | 12 |
| `jobs` | 执行器批次进度 | 15 |
| `operation_log` | 批量规则操作记录，可撤销 | 9 |
| `dict_refs` | 用过的字典名 + 内容哈希 | 6 |
| `export_schemes` | 导出方案 | 8 |

约定：

- 主键均为 `INTEGER PRIMARY KEY`（自增）。`image_id` 同时用作 `images/` 下的文件名主干。
- 时间字段为 `TEXT`，UTC ISO 8601。
- `*_json` 字段为 `TEXT`，存 JSON。
- 外键启用；删除图片不做物理删除（见 5.4 `review_status`），因此本版无级联删除场景 [待确认：项目内「彻底清理已剔除图片」是否提供]。
- 迁移：以 `project.json.format_version` 为准；`project.db` 内另设 `PRAGMA user_version` 与之对应 [待确认]。

### 5.2 sources

| 字段 | 类型 | 说明 |
|---|---|---|
| `source_id` | INTEGER | 主键 |
| `type` | TEXT | `import` / `nai` / 预留其它接口 |
| `name` | TEXT | 显示名 |
| `config_json` | TEXT | 数据源配置。NAI：生成参数（模型、步数、cfg 等）；import：导入选项 |
| `style_prompt` | TEXT | 画风正面词，用户输入。仅用于 NAI 出图，不进训练 caption。import 为空 |
| `negative_prompt` | TEXT | 画风负面词，用户输入。同上 |
| `target_count` | INTEGER | 目标数量。import 可为空 |
| `status` | TEXT | `draft` / `running` / `paused` / `done` / `canceled` |
| `locked` | INTEGER | 0/1。启动后置 1，参数锁定 |
| `created_at` | TEXT | 创建时间 |
| `started_at` | TEXT | 首次启动时间，同时是锁定时间 |
| `finished_at` | TEXT | 结束时间 |

状态机：

```
draft ──启动──▶ running ◀──继续── paused
                  │  └──暂停──▶ ─┘
                  ├──全部 item 终态──▶ done
                  └──取消──▶ canceled
```

- 锁定规则：`draft → running` 的瞬间 `locked=1`，此后 `config_json`、`style_prompt`、`negative_prompt`、`target_count` 不允许修改，仅 `name` 可改。要改参数就新建数据源，理由是保证同一数据源内参数一致。
- `done` 的判定：该数据源所有 `source_items` 均为 `done` 或 `failed`（`failed` 允许保留，不阻塞 `done`）。
- `import` 类型：启动即开始复制文件，文件级进度同样落在 `source_items`（见下）。
- `config_json` 中记录的导入原目录仅作溯源展示，运行时不读取，不违反「项目内只用相对路径」[待确认]。
- 画风提示词的拼接：发给 NAI 的完整串 = `style_prompt` + `source_items.prompt`；`quality_toggle` 固定关闭，`uc_preset` 必须为 None（见 7.3）。

### 5.3 source_items

| 字段 | 类型 | 说明 |
|---|---|---|
| `item_id` | INTEGER | 主键 |
| `source_id` | INTEGER | 外键 → `sources` |
| `seq` | INTEGER | 数据源内序号，与 `source_id` 联合唯一 |
| `prompt` | TEXT | 内容段提示词（不含画风串）。import 类型存原文件名 |
| `status` | TEXT | `pending` / `sent` / `done` / `failed` |
| `image_id` | INTEGER | 产出图片，可空，外键 → `images` |
| `attempts` | INTEGER | 已尝试次数 |
| `error` | TEXT | 最近一次失败原因 |
| `updated_at` | TEXT | 最近状态变更时间 |

状态机：

| 转移 | 条件 |
|---|---|
| `pending → sent` | 请求已发出（先落库再发请求） |
| `sent → done` | 结果收到，图片已入库，`image_id` 已回填（同一事务） |
| `sent → failed` | 明确失败，或崩溃恢复核查后确认未落盘 |
| `failed → pending` | 用户手动重试，`attempts` +1 |

幂等策略：

- 数据源启动时一次性生成全部 `source_items`（`seq` 固定、`prompt` 固定），续跑不重新抽取提示词。
- 续跑只处理 `pending`；`done` 永不重做。
- 崩溃恢复：启动时发现 `sent` 项，**不自动重放**（生成是付费类写操作，与 docs/04 F02「不重放写操作」一致），先核查图片是否已落盘：已落盘补成 `done`，否则转 `failed` 由用户决定是否重试 [待确认：核查手段取决于 docs/02 的 save_path 行为]。
- 一个 `image_id` 至多被一个 `source_items` 引用。

### 5.4 images

| 字段 | 类型 | 说明 |
|---|---|---|
| `image_id` | INTEGER | 主键，同时是 `images/` 下的文件名主干 |
| `filename` | TEXT | `images/` 下的相对文件名 |
| `width` | INTEGER | 像素宽 |
| `height` | INTEGER | 像素高 |
| `phash` | TEXT | 感知哈希，用于近似去重 |
| `sha256` | TEXT | 文件内容哈希，用于导入去重和缓存失效（图片指纹） |
| `file_size` | INTEGER | 字节数，视觉请求判定「≥10MB 也缩放」用 |
| `source_id` | INTEGER | 外键 → `sources`，**可空**；离开数据源层后来源不强制可追溯 |
| `review_status` | TEXT | `unreviewed` / `keep` / `reject`，默认 `unreviewed` |
| `png_meta_json` | TEXT | 入库时解析一次的 PNG 元数据；原图不动。非 PNG 或无元数据为空 |
| `created_at` | TEXT | 入库时间 |

`review_status` 只有三档：

| 值 | 含义 | 导出 |
|---|---|---|
| `unreviewed` | 未审 | 由导出方案过滤条件决定 |
| `keep` | 保留 | 导出 |
| `reject` | 剔除 | **跳过** |

- 三档之间可任意互转，无单向限制。
- **剔除只打标记，不删文件、不删行**，可随时恢复。
- 本版**不做** Danbooru 四级 `rating` 字段，只作为预留扩展点（见 12.1），不属于本表正式字段。
- `parent_id`（图片血缘）同属预留，不在本表正式字段内（见 12.2）。
- 幂等：导入前按 `sha256` 查重，命中则跳过并在 `source_items` 记录 [待确认：命中后是跳过还是提示用户]。`sha256` 不设唯一约束，因为 NAI 与导入可能出现相同内容。

### 5.5 annotations

分层存储，**互不覆盖**。不预先合并写回，最终 caption 由导出方案在导出时组合。

| 字段 | 类型 | 说明 |
|---|---|---|
| `annotation_id` | INTEGER | 主键 |
| `image_id` | INTEGER | 外键 → `images` |
| `source` | TEXT | 来源层：`original` / `wd` / `llm` / `manual` / `rule` |
| `type` | TEXT | `tags` / `nl`（自然语言） |
| `content` | TEXT | `tags`：JSON 数组，元素为 `{tag, conf}`，`conf` 可空；`nl`：纯文本 |
| `confidence` | REAL | 整条置信度，可空；逐 tag 置信度放 `content` 内 |
| `model_name` | TEXT | 实际使用的模型名；`original` / `manual` / `rule` 为空 |
| `params_json` | TEXT | 实际使用的参数：角色名、温度、阈值、缩放档位、NSFW 路由与 `rating_verified` 等 |
| `job_id` | INTEGER | 外键 → `jobs`，可空（手工和原始解析无 job） |
| `cache_key` | TEXT | 缓存键，由配置、模型、Skill 内容哈希、图片指纹组合而来（见 8.8） |
| `created_at` | TEXT | 写入时间 |
| `is_current` | INTEGER | 0/1，该层当前采用的版本 |

各层含义：

| `source` | 产生方式 | 典型 `type` |
|---|---|---|
| `original` | 原始提示词自动解析（标签段 / 自然语言段，见 8.2） | `tags`、`nl` |
| `wd` | 本地 WD tagger | `tags` |
| `llm` | LLM 视觉反推 | `tags`、`nl` |
| `manual` | 界面手工编辑 | `tags`、`nl` |
| `rule` | 批量规则操作结果（见 8.4） | `tags` |

规则：

- 同一 `(image_id, source, type)` 至多一条 `is_current=1`。重新执行不覆盖旧行，而是新增一行并把旧行置 0，历史保留。
- `original` 层只在导入/入库时写入；用户在界面修改解析结果时写入 `manual` 层，不改 `original` [待确认]。
- 「原始 + LLM 视觉改进后两份自然语言并存」靠 `source` 区分，无需额外字段。
- 幂等：执行器写入前按 `(image_id, source, type, cache_key)` 查当前行，命中则跳过（见 8.3）。
- `is_current` 只表示该层的当前版本；导出时取哪些层、按什么优先级，由导出方案决定（见第 10 章）。

### 5.6 jobs

执行器批次进度。**启动时冻结配置快照**，运行期间产品层配置变化不影响本批次。

| 字段 | 类型 | 说明 |
|---|---|---|
| `job_id` | INTEGER | 主键 |
| `executor` | TEXT | 执行器：`wd` / `llm_vision`，预留其它 |
| `mode` | TEXT | `selected`（执行选中）/ `uncovered`（执行未覆盖）/ `all`（执行所有） |
| `scope_json` | TEXT | 范围：`selected` 存 image_id 列表；其余存筛选条件（如数据源、审图状态） |
| `config_snapshot_json` | TEXT | 冻结的配置快照：角色名、实际模型名、协议格式、采样参数、阈值、缩放档位、并发/超时/重试参数、Skill 内容哈希。**不含端点地址和密钥** |
| `status` | TEXT | `pending` / `running` / `paused` / `done` / `failed` / `canceled` |
| `total` | INTEGER | 启动时计算出的待处理张数 |
| `done_count` | INTEGER | 成功张数 |
| `failed_count` | INTEGER | 失败张数 |
| `skipped_count` | INTEGER | 因缓存命中或 NSFW 角色为空等原因跳过的张数 |
| `error` | TEXT | 批次级错误（如角色未配置） |
| `created_at` | TEXT | 创建时间 |
| `started_at` | TEXT | 启动时间，即快照冻结时间 |
| `finished_at` | TEXT | 结束时间 |
| `updated_at` | TEXT | 最近进度更新时间 |

状态机：

```
pending ──启动(冻结快照)──▶ running ◀──继续── paused
                              │  └──暂停──▶ ─┘
                              ├──处理完毕──▶ done
                              ├──批次级错误──▶ failed
                              └──取消──▶ canceled
```

幂等与续跑：

- 执行器没有逐图的 job 子表。续跑时按 `mode=uncovered` 的同一判定重新计算：某图在目标层已有 `cache_key` 相同的当前行即视为已覆盖。因此中断后重启同一 job 不会重复调用 LLM。
- 「执行未覆盖」的覆盖判定 = 该 `(image_id, source, type)` 存在 `is_current=1` 且 `cache_key` 与当前快照计算结果一致。
- 进程崩溃时 `running` 的 job 在下次启动转为 `paused`，由用户决定继续 [待确认]。
- 并发上限 2、退避重试、超时等参数来自快照，不读运行时配置。

### 5.7 operation_log

批量规则操作记录，可撤销。规则语义见 8.4。

| 字段 | 类型 | 说明 |
|---|---|---|
| `op_id` | INTEGER | 主键 |
| `rule_json` | TEXT | 规则全文：删除/写入/条件三组 tag 及各自「全量」「任意」模式 |
| `scope_json` | TEXT | 作用范围，同 `jobs.scope_json` |
| `affected_count` | INTEGER | 实际发生变更的图片数 |
| `changes_json` | TEXT | 逐图变更清单：`image_id`、新增的 `annotation_id`、被置为非当前的 `annotation_id` |
| `status` | TEXT | `applied` / `undone` |
| `created_at` | TEXT | 执行时间 |
| `undone_at` | TEXT | 撤销时间 |
| `note` | TEXT | 用户备注 |

- 规则结果写入 `annotations`（`source=rule`，`type=tags`），不改动其它层。
- 撤销 = 按 `changes_json` 把新增行置 `is_current=0`，并恢复被置 0 的旧行。因为标注分层不覆盖，撤销无需存全量副本。
- 撤销顺序：仅允许撤销最近一次 `applied` 的操作，或在涉及的图片上无后续变更时撤销更早的操作 [待确认]。
- 幂等：同一规则对同一图片重复执行，若结果与当前 `rule` 层一致则不产生新行、不计入 `affected_count`。

### 5.8 dict_refs

项目只记录用过的字典，不存内容（决议见 4.4）。

| 字段 | 类型 | 说明 |
|---|---|---|
| `ref_id` | INTEGER | 主键 |
| `dict_name` | TEXT | 产品层字典名 |
| `dict_type` | TEXT | `feature`（特征字典）/ `prompt`（提示词词典） |
| `content_hash` | TEXT | 使用时刻的字典内容哈希 |
| `source_id` | INTEGER | 外键 → `sources`，可空；记录由哪个数据源使用 |
| `recorded_at` | TEXT | 记录时间 |

- 同一 `(dict_name, content_hash, source_id)` 只记一条。
- 打开项目时对每个 `dict_name` 取最新一条记录与当前字典哈希比对，不符则提示「字典已变更」；仅提示，不阻止打开。
- 「特征词典现场生成」产生的特征没有稳定字典名，记录生成源名称与版本 [待确认：生成源的哈希口径]。

### 5.9 export_schemes

| 字段 | 类型 | 说明 |
|---|---|---|
| `scheme_id` | INTEGER | 主键 |
| `name` | TEXT | 方案名 |
| `exporter` | TEXT | 导出器类型。默认 `image_txt`（图片 + 同名 txt），其余预留 |
| `filter_json` | TEXT | 图片过滤：`review_status` 范围（`reject` 恒跳过）、数据源范围 |
| `caption_config_json` | TEXT | caption 组合：各 `source` 层优先级、是否带自然语言、触发词位置、排序、分隔符 |
| `output_config_json` | TEXT | 输出选项：输出子目录、文件命名、是否输出配套 json |
| `created_at` | TEXT | 创建时间 |
| `updated_at` | TEXT | 更新时间 |

- 项目创建时自动建一条默认方案（`image_txt`）。
- 导出是只读操作：不改 `images`、`annotations`。
- 幂等：重复导出到同名目录时先清空该方案目录再写 [待确认：是否改为带时间戳新目录]。

### 5.10 一致性约定

| 项 | 约定 |
|---|---|
| 事务边界 | `source_items → done` 与 `images` 入库、`annotations` 的新增/置非当前，各自在同一事务内完成 |
| 外键 | 开启；`images.source_id`、`source_items.image_id`、`annotations.job_id` 允许空 |
| 索引 | `annotations(image_id, source, type, is_current)`、`source_items(source_id, status)`、`images(review_status)`、`images(sha256)`、`images(phash)` [待确认：以实际查询为准] |
| 并发 | SQLite WAL 模式，单进程单写连接；执行器并发 2 仅指对外 API 请求并发，写库串行 |
| 迁移 | 见 5.1 |

## 6. 提示词生产机制

提示词生产层为生成类数据源（NAI 等）提供内容段提示词。import 数据源不经过本层。

### 6.1 流程

```
特征字典 / 特征生成源
        │  按过滤规则随机组合（受围栏开关约束）
        ▼
   特征组合
        │  可选：LLM 优化（角色 prompt / prompt_nsfw）
        ▼
   提示词词典（产品层，可追加条目）
        │  随机抽取（词典多选 + 现场生成开关 + 数量）
        ▼
   source_items.prompt（启动数据源时一次性固定）
```

### 6.2 方向：随机 + 字典混合

- 字典约束主维度，保证覆盖；随机填充其余维度，保证多样性。
- 具体维度与配比**延后设计**（沿用 docs/04 §6 方向）。本文档只写机制预留：维度、配比、约束均为配置内容，不进代码常量。

### 6.3 机制预留点

| 机制 | 设计 |
|---|---|
| 特征字典导入 | 可导入外部特征字典，存产品层字典库 |
| 特征生成源 | 可接入「特征生成源」，如 NAI Launcher 的随机提示词词库；现场生成特征，不落字典 |
| 围栏开关 | 首个围栏为 **NSFW 围栏**（开：组合时排除 NSFW 特征）。围栏以开关列表形式组织，预留扩展位，其它围栏本版不定义 |
| 过滤规则 | 按规则筛选特征后再随机组合；规则语法 [待确认] |
| LLM 优化（可选） | 把特征组合交给 `prompt` 角色优化；NSFW 内容走 `prompt_nsfw`，该角色为空则不做 LLM 清洗（见第 9 章）。运行时 Skill 见 docs/06 R1 |
| 存入提示词词典 | 优化结果存入用户指定的自定义提示词词典；LLM 优化结果可直接追加条目 |
| 词典导入导出 | 提示词词典可导入导出 |
| 随机抽取 | 抽取时可选来源：提示词词典（多选）+「特征词典现场生成」开关；并指定数量 |

### 6.4 与项目的衔接

- 抽取结果在数据源启动时写入 `source_items.prompt` 并固定，续跑不重新抽取（见 5.3）。
- 用到的字典记入 `dict_refs`（见 5.8）；LLM 优化实际使用的模型名与参数随结果记录 [待确认：提示词词典条目的溯源字段放产品层词典内，项目侧不存]。
- 提示词内容段**不含画风串**；画风串在 NAI 出图时由数据源拼接（见 7.3）。

## 7. 数据源机制

### 7.1 通用规则

| 项 | 规则 |
|---|---|
| 平行关系 | `import`、`nai`、其它接口数据源地位平行，共用 `sources` / `source_items` 结构 |
| 参数锁定 | 数据源启动后参数锁定，不允许更改（状态机见 5.2） |
| 目标数量 | `sources.target_count`；NAI 为生成张数，import 可空 |
| 产出 | 每张产出图片登记 `images`，并回填 `source_items.image_id` |
| 来源可追溯性 | `images.source_id` 可空：离开数据源层后不强制可追溯 |
| 生成参数粒度 | 生成参数在数据源级（`config_json`），**不以图片为单位保存**，不影响后续处理和训练 |
| 参考图字段 | 生图请求结构从一开始带可选的参考图字段（本版不填，见 12.3） |

### 7.2 外部导入（import）

- 选择文件或目录，逐文件**复制进项目** `images/`，不引用原位置。
- 复制后计算宽高、`phash`、`sha256`、`file_size`，登记 `images`。
- PNG 元数据入库时解析一次写入 `images.png_meta_json`，原图不动。
- 原始提示词若能从元数据取得（如 NAI 的 `prompt` 字段），自动解析写入 `annotations`（`source=original`，见 8.2）。其它来源的元数据格式（如 WebUI 的 parameters）[待确认]。
- 重复文件按 `sha256` 处理，见 5.4。

### 7.3 NAI 数据源

通过 Aaalice NAI Launcher 的 MCP 接口生图。连接方式、生成链路、工具分级、稳定性处理均见 docs/02，本文不重复。

| 项 | 设计 |
|---|---|
| 生成参数 | 模型、步数、cfg 等由前端配置，存 `sources.config_json`；默认 V5 标准版 `nai-diffusion-5-full` |
| 表单来源 | 前端不硬编码参数项，向后端能力自描述接口取 schema 后动态渲染（沿用 docs/04 §2.1） |
| `quality_toggle` | **固定关闭**，不暴露给前端 |
| `uc_preset` | **必须设 None**，否则用户负面词会被预设顶掉 |
| 画风正/负面词 | 不内置，由用户在前端输入，存 `sources.style_prompt` / `negative_prompt`；调用时与内容段拼接：完整正面串 = `style_prompt` + `source_items.prompt` |
| 画风提示词用途 | **只用于 NAI 出图**，不进训练 caption |
| 训练 caption 的画风处理 | 不是「剔除画风词」，而是「只取内容段 + 前挂触发词」；触发词来自 `project.json.trigger_word` |
| 生成参数粒度 | 不以图片为单位保存 |

| 账号状态 | 预留只读展示口子（额度等）；不参与任何决策；字段全部可选（沿用 docs/04 §2.1） |

执行约束（引用 docs/02，不展开）：

- 写操作串行、不重放未完成写操作；崩溃恢复处理见 5.3。
- 0 Anlas 守卫等费用相关策略 [待确认：docs/04 §5 决议 7 说费用归 Launcher 管，但 F04 守卫是否保留需重新确认]。

## 8. 数据清洗工作台

从 TagCleaner 迁移的能力。工作台是产品主界面，数据源只是图片的入口。

### 8.1 数据集视图与图片详情

数据集视图展示**所有数据源的所有图片**及打标状态。

| 列/信息 | 来源 |
|---|---|
| 缩略图 | `cache/`，可重建 |
| 数据源 | `images.source_id`（可空） |
| 审图状态 | `images.review_status` |
| 各层打标状态 | `annotations` 中各 `source` 是否存在 `is_current=1` |

选中图片后展示：

| 区块 | 内容 |
|---|---|
| 标签列表 | 当前标签 + 中文翻译（标签翻译库，产品层） |
| WD 对照 | WD 完成后展示反推结果与原始标签的重合情况，及每个 tag 的置信度 |
| 自然语言 | 原始（`original`）与 LLM 视觉改进后（`llm`）**两份并存**展示 |
| 审图操作 | 切换 `unreviewed` / `keep` / `reject` |

### 8.2 原始提示词解析

- 入库时把原始提示词**自动解析为标签段和自然语言段**，写入 `annotations`（`source=original`，`type=tags` / `nl`）。
- 解析规则：按逗号分段；能在标签库查到的算 tag，查不到的算自然语言。
- 界面可手改解析结果；手改写入 `manual` 层，不覆盖 `original`（见 5.5）。
- 「标签库」即产品层标签翻译库 [待确认：是否另有独立的 Danbooru tag 表]。
- 归一化细节（下划线与空格、大小写、权重语法）[待确认]；docs/02 实测 NAI 会把 `_` 转为空格，对比时需统一归一化。

### 8.3 执行器与执行模式

执行器列表（可多选）：

| 执行器 | 写入层 | 依赖 |
|---|---|---|
| WD 打标 | `wd` / `tags` | 本地 WD tagger（见 8.7） |
| LLM 视觉反推 | `llm` / `tags`、`nl` | 角色 `vision`（NSFW 时 `vision_nsfw`），模型需标记「支持图像」 |

三种模式：

| 模式 | 范围 | 对应 `jobs.mode` |
|---|---|---|
| 执行选中 | 当前选中的图片 | `selected` |
| 执行未覆盖 | 目标层尚无有效结果的图片 | `uncovered` |
| 执行所有 | 全部图片，已有结果也重跑 | `all` |

- 「未覆盖」判定：目标 `(image_id, source, type)` 存在 `is_current=1` 且 `cache_key` 与当前快照一致（见 5.6、8.8）。
- 启动时冻结配置快照到 `jobs.config_snapshot_json`；多选执行器时是否拆成多个 job [待确认]。
- `reject` 图片是否参与执行器 [待确认]。
- 每条结果记录实际模型名与参数（`annotations.model_name`、`params_json`），不依赖产品配置还原。

### 8.4 批量规则替换

规则由三组多 tag 列表组成，每组各有「全量」「任意」两种模式。

| 组 | 全量 | 任意 |
|---|---|---|
| 删除 | 列表**全部存在**才执行，删除全部 | **任一存在**即执行，只移除命中项 |
| 写入 | 列表**全部不存在**才执行，写入全部 | **有缺失**就执行，只补缺失项 |
| 条件 | [待确认：推断为全部存在 / 任一存在才满足] | 同左 |

规则：

- **条件用原始 tags 判断**（`original` 层，不受其它层影响）。
- 删除与写入同时存在时，**删除成功才判断写入**；删除未执行（条件不满足或无命中）则写入不执行。
- 只有写入组时，直接按写入组模式判断。
- 条件组未满足时整条规则对该图不执行。
- 删除/写入的作用对象：当前采用的 tags 视图（各层合并结果）[待确认：对哪一层读取、写入 `rule` 层的内容是完整快照还是增量]。
- 结果写入 `annotations`（`source=rule`），并记 `operation_log`，可撤销（见 5.7）。
- 先预览命中图片数与示例，确认后再执行 [待确认]。

### 8.5 并发、重试与超时

| 项 | 设计 |
|---|---|
| 并发上限 | 2（对外 API 请求并发） |
| 重试 | 退避重试；429 先切换令牌（见 4.2） |
| 单次 API 超时 | 默认 300s，来自 job 快照 |
| 限流与服务端错误 | 不触发图片压缩降档（见 8.6） |

### 8.6 视觉请求的图片处理

视觉请求对图片缩放为**内存 JPEG 副本**，**原图不改**，不落盘。

| 项 | 设计 |
|---|---|
| 默认档 | 2MP |
| 大文件 | 原图 ≥ 10MB 也缩放 |
| 超时降档 | 超时后降到 1.6MP / 1MP，JPEG 质量 88 / 84 |
| 不触发降档 | 限流（429）和服务端错误 |
| 溯源 | 实际使用的缩放档位记入 `annotations.params_json` |

默认档的 JPEG 质量 [待确认：未给定]；1.6MP 对应质量 88、1MP 对应质量 84 为按顺序对应的推断 [待确认]。

### 8.7 WD tagger

- 本地可选组件，**从源下载不打包**。
- 走画风 LoRA 线时**默认不开启**。
- 显存由产品启动时自动读取（nvidia-smi / pynvml），用于决定可用的本地模型。
- 读取失败时的降级行为 [待确认]。

### 8.8 缓存与失效

执行结果缓存键 `annotations.cache_key` 由以下四项组合：

| 要素 | 说明 |
|---|---|
| 配置 | job 快照中的相关参数 |
| 模型 | 实际模型名 |
| Skill 内容哈希 | 运行时 Skill 文本哈希（见 docs/06） |
| 图片指纹 | `images.sha256` |

四项**任一变化即失效**，失效后「未覆盖」判定将该图视为未覆盖。旧结果不删，按分层规则保留为历史行。

## 9. NSFW 路由

本版**不依赖 `images.rating` 字段**。路由结果在每次请求时现算，实际走的线路记入对应 `annotations.params_json`（见 9.4）。

### 9.1 判定优先级

| 优先级 | 判定方式 | 说明 |
|---|---|---|
| 1 | 关键词词库匹配 | 产品层 NSFW 关键词表，格式 `tag<TAB>等级`；图片/提示词的 tag 命中即得出结论 |
| 2 | 分级模型 | 用户可配置角色 `rating`；**手动指定时**才用它分析 |
| 3 | `nsfwfallback` 策略 | 用户可把策略指定为 nsfwfallback：所有不确定内容全部走 nsfw 线路 |
| 兜底 | 走普通处理 | 三者都没配置，或都没结论时走普通线路，并在发给 LLM 的请求体里标注 `rating_verified: false` |

- 判定自上而下，前一项有结论即停止。
- `nsfwfallback` 是策略项：启用后，前两项都无结论的内容一律走 nsfw 线路，因此兜底分支不会出现。
- `rating_verified` 为 `true` 的条件：由 1 或 2 得出结论 [待确认：由 3 得出的是否算 verified]。

### 9.2 两条线路

| 线路 | 提示词生产 | 视觉反推 |
|---|---|---|
| 普通 | `prompt` | `vision` |
| nsfw | `prompt_nsfw` | `vision_nsfw` |

nsfw 线路对应角色为空时：**跳过该 LLM 步骤，保留原值**（不报错，计入 `jobs.skipped_count`）。

### 9.3 `refused_nsfw` 短路

- 普通线路下，若请求带 `rating_verified: false`，LLM 发现明确 NSFW 内容时**立即短路返回** `refused_nsfw`，不做任何处理或净化改写（Skill 侧规则见 docs/06 R0）。
- 产品收到 `refused_nsfw` 后改走 nsfw 线路重新请求；若 nsfw 角色为空，按 9.2 跳过该步骤、保留原值。
- 同一图片同一步骤至多重路由一次，避免循环。
- docs/06 R0 写作「把该图 rating 升为 `questionable`」，该字段本版不存在，改为只影响本次路由，见 9.4 与第 13 章。

### 9.4 溯源记录

写入 `annotations.params_json` 的路由信息：

| 键 | 含义 |
|---|---|
| `route` | `normal` / `nsfw` |
| `route_reason` | `keyword` / `rating_model` / `nsfwfallback` / `refused_nsfw` / `default` |
| `rating_verified` | 布尔 |

- 路由相关配置（关键词表、`rating` 角色、nsfwfallback）冻结在 `jobs.config_snapshot_json`。
- NSFW 关键词表内容变化是否使缓存失效 [待确认：8.8 的四要素未包含它]。

## 10. 导出机制

### 10.1 原则

- 导出方案存 `export_schemes`，可配置；默认方案为「图片 + 同名 txt」。
- 其余格式（如 kohya 目录结构）只做扩展规划，导出器抽成接口（见 12.4）。
- **最终 caption 在导出时组合**，不预先合并写回 `annotations`。
- 导出只读，不改 `images`、`annotations`。

### 10.2 默认方案 `image_txt`

| 步骤 | 规则 |
|---|---|
| 图片过滤 | 排除 `reject`；其余按方案 `filter_json`（如仅 `keep`，或 `keep` + `unreviewed`） |
| 图片输出 | 复制 `images/` 中的原图到 `exports/` 下方案目录；原图不改 |
| caption 组合 | 按 `caption_config_json` 取各 `source` 层的 `is_current=1` 行，按优先级合并去重 |
| 触发词 | 取 `project.json.trigger_word`，固定排在 caption 第一位 |
| 画风部分 | 只取内容段，前挂触发词；**不含任何 `style_prompt` 内容** |
| 自然语言 | 方案可选是否追加；选哪一层（`original` / `llm` / `manual`）由方案配置 |
| 文件名 | 同名 txt，主干与图片一致 |
| 可选输出 | 配套 json（来自 `images.png_meta_json`）；统计报告 [待确认] |

### 10.3 caption 组合可配置项

| 配置 | 说明 |
|---|---|
| 层优先级 | 例如 `manual` > `rule` > `llm` > `wd` > `original` [待确认：默认顺序] |
| 合并策略 | 取最高优先级单层，或多层并集去重 [待确认] |
| tag 排序 | 沿用 docs/06 R4 的顺序（触发词 → 主体 → 动作表情 → 服装 → 构图 → 场景 → 光照） [待确认] |
| 受保护 tag / 黑名单 | 内容段混入画风词时剔除并记日志（沿用 docs/04 §2.2 blocklist 作为保险） [待确认] |
| 分隔符 | 逗号 + 空格 |

### 10.4 导出前检查

- 触发词必填，且不得出现在任何 `style_prompt` 中；是否与 Danbooru 已有 tag 冲突，警告但允许强制通过（沿用 docs/04 §5 决议 8）。
- 字典哈希不符提示「字典已变更」只在打开项目时触发，不阻止导出。
- 有 `unreviewed` 图片且方案要求仅 `keep` 时，导出前提示数量。

## 11. 技术栈与进程结构

### 11.1 技术栈

| 部分 | 选型 |
|---|---|
| 后端 | FastAPI；绑 `127.0.0.1`，**启动时生成随机 token**，前端请求带 token |
| 前端 | React + Vite + TypeScript |
| 存储 | SQLite（`project.db`），WAL 模式 |
| 桌面外壳 | Tauri，**后期**再做 |
| 已否决 | Svelte、Gradio / Streamlit、Flutter |

### 11.2 进程结构

```
┌ 前端 (React + Vite + TS) ─────────────────────────┐
│ 项目管理 │ 数据集视图 │ 详情/审图 │ 数据源 │ 设置 │
└───────────────┬────────────────────────────────────┘
                │ HTTP, 127.0.0.1 + 随机 token
┌───────────────▼────────────────────────────────────┐
│ FastAPI 后端（单进程）                              │
│  项目服务 │ 数据源服务 │ 执行器/Job │ 导出服务      │
│  适配器：LLM 协议(插件) │ ImageBackend │ WD tagger   │
└───┬───────────────┬──────────────────┬─────────────┘
    │               │                  │
 项目目录         产品层配置          外部服务
 (project.db     (端点/角色/字典/    (LLM 端点、
  images/…)       secrets.json…)      NAI Launcher MCP)
```

### 11.3 安全要点

- 后端无登录体系，仅靠 127.0.0.1 绑定与随机 token 做访问控制；不得绑定 0.0.0.0。
- 本地 API 不返回密钥明文（见 4.3）。
- token 每次启动重新生成，不落盘 [待确认：前端如何获得 token，如启动参数传递或由外壳注入]。
- 一次打开一个项目还是允许多个同时打开 [待确认]。
