# 01 开发分工调度表

> 模型定位依据：端点实测（延迟/可用性）+ 模型档位。各模型真实能力（尤其视觉输入）未做基准测试，跑过首轮任务后再调整。

## 1. 开发阶段分工

| 板块 | agent | 模型 | 备选 | 理由 |
|---|---|---|---|---|
| 架构规划 | 主线（当前会话）/ `architect` | opus55 | — | 跨模块取舍、决策需要最强推理 |
| 模块设计 | `module-designer` | gpt6astra | opus55 | 把架构拆成接口/状态机/测试清单 |
| 依赖探查 | `dep-scout`、内置 `explore` | deepseekv41f | glm53 | 只读调查，量大、要快要便宜（实测 1.8s） |

| 代码审查 | `reviewer`（只读） | gpt61sol | opus55 | 和实现者（gpt6astra）异构审查；重点查幂等、重复扣 Anlas、密钥 |
| 前端设计 + 美术设计 | `frontend` | sonnet55 | opus55（交互/视觉方案） | 前端代码质量与 UI 审美均衡；负责设计令牌与主题体系 |
| 索引与文档 | `doc-writer` | sonnet55 | kimik3 | 通读仓库写索引与文档 |
| 通用子任务 | 内置 `general` | sonnet55 | — | 覆盖原来失效的 newapi 配置 |

模型分配调整（2026-10-12）：module-designer 与 coder-lite 互换；主力实现改用 gpt6astra；doc-writer 由 kimik3 改为 sonnet55。

调度规则：

- 主线（opus55）只做决策、拆任务、验收，不亲自写批量代码。
- 规格不明确的任务不下发给 `coder-lite`，先回到 `module-designer`。
- 每个模块走一遍：设计 → 实现 → 审查 → 主线验收。审查发现阻断问题，打回原实现者修改，不换人。
- 涉及花 Anlas、删文件、改 Launcher 设置的操作，任何 agent 都只能写代码，不能自己执行，由人确认。
- **subagent 上下文控制（2026-10-13 用户规则）**：subagent 上下文过长且任务不需要高连续性时，及时重开新会话压缩上下文，不 resume 旧会话。新会话只给必需的读取范围（按章节/行号限定，不让它通读大文档），篇幅和条目数在任务说明里限定。
- 写文件按工具限制分块（每块 ≤50 行/4000 字符），任务说明里要求每块写满、不回读已写内容，减少轮次。

**subagent 调度**：已验证通过，10/10。

- 首次测试失败，原因是配置而非模型：全局 `~/.config/opencode/opencode.json` 把内置 `explore`/`general` 指向 `newapi/deepseek-v4-*`，而 `opencode.jsonc` 里 `newapi` 被 disabled，报 `Model not found`。
- 已在项目根新建 `opencode.json`，覆盖 `explore`→deepseekv41f、`general`→sonnet55。
- 已建 8 个项目 agent：`.opencode/agents/{architect,module-designer,dep-scout,implementer,coder-lite,reviewer,frontend,doc-writer}.md`。
- opencode 不热加载配置，重启后复测：8 个项目 agent + 内置 `explore`/`general` 全部正常返回，跨端点（sc-claude / sc-gpt-astra / sc-gm）调度可行。
- 结论：后续改 agent 模型或新增 agent，都要重启 OpenCode 才生效。

**顺带发现的配置问题**（建议你自己处理，我没动全局配置）：

- 全局目录下 `opencode.json` 和 `opencode.jsonc` 并存，且 `sc-claude` 的定义不一致（一个用 openai-compatible 不带 `/v1`，一个用 `@ai-sdk/anthropic` 带 `/v1`）。建议合并成一个文件。
- API key 明文写在配置里，建议改成 `{env:VAR}` 或 `{file:path}`。
- 图片输入（2026-10-13 已修）：全局配置里 sc-claude 的 opus55/sonnet55 原先未声明 `attachment`/`modalities`，OpenCode 把它们当纯文本模型、拦下图片。已在 `opencode.json` 与 `opencode.jsonc` 补 `attachment: true`、`modalities.input: [text, image]`，重启后主线读图实测成功。其余模型的图片能力仍未测。
