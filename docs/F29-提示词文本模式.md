# F29 提示词文本模式

状态：方案草案，暂不实现。本文所有"应用点"均为后续实现；与现有行为不一致处以代码和 docs/05 为准。

## 1 背景与三种模式

- NAI 提示词倾向自然语言与 tag 混写（同一串里逗号段既有 tag 也有句子）。
- Anima 倾向 tag 行与英文自然语言段分开：第 1 行 tag，空行，其后 NL 段（与 docs/05 §10 caption txt 的行结构一致）。

由此抽象三种文本模式（字段名 `text_mode`）：

| 值 | 含义 | NAI 形态 | Anima 形态 |
|---|---|---|---|
| `tag` | 纯 tag | 逗号分隔 tag | 逗号分隔 tag（单行） |
| `tag_nl` | tag + 自然语言 | 混写：tag 与句子在同一逗号串中 | tag 行 + 空行 + NL 段 |
| `nl` | 纯自然语言 | 一段或多句英文 | 一段英文 NL |

### 2.3 反推（打标）与二次清洗

可指定写入模式。**待讨论（做到此处时与用户确认）**：只写一种模式，还是三种都存、导出时按规则选取/组合。

| 维度 | 方案 A：只写一种（由任务指定） | 方案 B：三种都存，导出时选取/组合 |
|---|---|---|
| 存储结构 | 沿用 `annotations` 的 `type=tags/nl`，不新增类型；模式仅体现在 params_json 或隐含于 type | tag 与 nl 本就分开存；`tag_nl` 无需存储，导出时拼接，实际只需保证 tag 与 nl 两层都有 |
| 编辑成本 | 低：每图一份结果，改动少 | 较高：要维护多份且保持语义一致，tag 改了 nl 可能过期 |
| 导出灵活性 | 低：换模式需重跑反推/清洗 | 高：同一数据集可导出 tag / tag_nl / nl 多套 |
| 与现有 caption txt 兼容 | 完全兼容（第 1 行 tags、空行、NL 段） | 兼容：导出结果仍是同结构；`nl` 模式需新增"只写 NL"的输出规则 |
| LLM 调用量 | 少（一次一种） | 多（需 tags 和 nl 两类产出；现有 `llm` 层已同时产 tags 与 nl，增量有限） |

结论暂缺。注意 docs/05 §5.5 的分层存储本身已让方案 B 的"存储"部分近乎免费，主要成本在导出规则与 UI。

### 2.4 导出

caption txt 按导出规则选择模式。落点是 `export_schemes.caption_config_json`（docs/05 §10.3）新增一项，例如 `text_mode`；默认值 [待确认]，应保持当前行为（现默认自然语言关闭，即等价 tag）。

## 4 与 F28 转换器的关系

- 转换器只处理 tag 部分的语法（括号权重、下划线、转义）。
- NL 行原样透传，不做权重、转义、下划线改写。
- Anima→NAI 方向按行识别自然语言行：含句末标点，或任一逗号段 ≥4 词。命中则整行透传，其余行按 tag 转换。
- 方向与模式的组合：`tag_nl` 在 NAI 为混写（单行内混入句子）、在 Anima 为分行。NAI→Anima 时是否把混写拆为"tag 行 + NL 段"属本方案范围，F28 当前不做 [待确认]。
