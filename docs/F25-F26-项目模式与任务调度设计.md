## 2 F25 ModeProfile

### 2.1 职责、字段与差分

新增 modes/profiles.py：提供不可变策略表、版本解析、能力描述；业务调用者按策略键调用现有组件，不分散编写 `if mode == ...`。
类型：`ModeId = str`（已注册 style/character，action/object 仅名称预留）；`PolicyRef = str`；`TemplateRef = {variant: str, content_hash: str | None, enabled: bool}`。
`ModeProfile` 字段如下；character 栏是不可执行的设计预留，不能作为已具备功能发布。

| 字段（类型） | style 实值 / 行为 | character 预留值 / 行为 |
|---|---|---|
| mode: ModeId；revision: int；enabled: bool | style；1；true | character；1；false |
| display_name: str | 画风模式 | 角色模式 |
| templates: Mapping[str, TemplateRef] | R1=style/content；R2=style/visible-content；R3=style/clean（禁用） | R1=character/content；R2=character/visible-features；R3=character/clean（均禁用） |
| dataset_mode_policy: str | style：只描述可见内容，不描述画风/笔触/媒介 | character：保护可见身份特征；规则文本待角色线定义 |
| blocklist_policy: PolicyRef | style-content-v1：画风段词、画师与 A–J 规则；保留现有例外 | character-protect-v1：身份特征优先保护，不套用画风词全删策略 |
| protected_tags_policy: PolicyRef | trigger-v1：触发词保护；与 blocklist 冲突报错 | identity-v1：触发词、角色标识、已确认外观特征；冲突转人工审阅 |
| trigger_semantics: str | style_identity：触发训练画风，不当内容描述词 | character_identity：绑定角色身份 |
| caption_order: tuple[str, ...] | trigger, subject, action_expression, clothing, composition, scene, lighting, nl | trigger, identity_features, action_expression, clothing, composition, scene, lighting, nl |
| default_sort: str；blocklist_action: str | preserve；warn（保留当前行为）；remove 仍须显式选择 | reserved；reserved |
| statistics_policy: PolicyRef | content-coverage-v1：图幅、rating、审核状态、内容维度覆盖及画风泄漏数 | identity-coverage-v1：身份一致性、服装/姿态/视角覆盖、缺失特征数 |
| generation_policy: PolicyRef | existing-content-v1：保持既有内容请求，不自动补角色身份或参考图 | character-reference-v1：预留身份绑定与角色参考图映射 |
| qc_policy: PolicyRef | visible-content-v1：画风禁词、疑似词待审、触发词冲突、空 caption；评级保持原路由 | identity-consistency-v1：缺失/冲突身份特征、参考图一致性；R6 A-pose 另行启用 |
| capabilities: frozenset[str] | mode.style；已存在功能仍受各自 availability 约束 | 空；所有执行入口返回 mode:unsupported |

表中 caption_order 是启用排序时的语义顺序；默认 preserve 不擅自重排已有标签，trigger 始终首位，NL 仍为独立尾段。
style 模板必须从现有冻结文本生成 hash；表不伪造 hash。缺 R2 返回 skill_unavailable；R3/R6 不注册执行器。
blocklist 的 warn/remove 是动作，项目 mode 是数据集类型，两者类型与参数名必须分开；保护列表不能绕过触发词冲突或输出契约校验。
统计分母：同一查询快照内可用图片数；rating/review 分组包含 unknown；覆盖用现有内容维度，泄漏用 QC 命中图片去重，不用命中词数冒充图片数。
`GenerationPolicy.apply(request: GenerationRequest, context: ModeContext) -> GenerationRequest`：沿用后端已有 characters[] 与参考图 DTO，不添加未经能力声明的字段。
style 的 characters[]/参考图保持既有显式内容配置与能力校验；默认空，不将 style_prompt 或 trigger 自动转为角色字段；character 将来须按身份与参考图用途显式映射。

### 2.2 公开接口、依赖与快照

- `get_profile(mode: ModeId, revision: int | None = None, *, executable: bool = True) -> ModeProfile`；未知 mode 报 mode:unknown，预留 mode 执行报 mode:unsupported。
- `freeze_profile(profile: ModeProfile) -> ProfileSnapshot`；`ProfileSnapshot = {mode: str, revision: int, digest: str, policies: Mapping[str, str], template_hashes: Mapping[str, str]}`。
- `resolve_profile(snapshot: ProfileSnapshot) -> ModeProfile` 验证 digest 与版本；缺旧版本报 profile:unavailable 并暂停，不偷偷用最新版续跑。
- `ModeContext = {profile: ProfileSnapshot, trigger: str, protected_tags: tuple[str, ...]}`；由项目快照或显式产品任务上下文提供，不从当前打开项目隐式读取。
- 依赖：已有 SkillStore、标签目录、caption 校验与快照机制；纯表解析不访问数据库。规则正文同模板一并按内容版本冻结。
- 缓存键及任务输入摘要纳入 profile digest、模板 hash、Formatter 版本；旧缓存只有能证明等价 style-v1 才复用，否则正常失效。
- 幂等：同 mode/revision 得到相同 profile；相同输入与版本得到同一摘要；模式解析失败不启动调用。最小测试 T01–T05。

### 2.3 project.json 迁移

`ProjectMetadata` 追加 `mode: str = 'style'`；`create_project(root: Path, *, name: str, trigger_word: str, mode: str = 'style') -> ProjectHandle` 只接受可执行模式。
`update_metadata(project: ProjectHandle, *, name: str, trigger_word: str) -> ProjectMetadata` 保留 mode 和 format_version；首版不提供修改项目模式的接口。
迁移沿用现有版本协调机制：定义 N=实施时 CURRENT_VERSION、目标 N+1；同时登记 JSON 补字段迁移与 DB 空结构迁移（只推进版本，不增表）。这是 C35 的具体方案。
打开流程在持有 ProjectLock 后先解析原始 JSON、检查版本，再构造 DTO；旧版本缺 mode 归一为 style，旧版本显式未知 mode 不覆盖；新版本缺 mode 视为损坏。
新建写目标版本及 mode=style；打开旧项目 migrate=false 报 Migration required；migrate=true 走现有迁移标记、备份、恢复机制，再原子发布 JSON。
迁移入口必须判断 JSON 与 DB 两者是否需升级，不能继续仅依赖 `version != CURRENT_VERSION`；半迁移由标记恢复，禁止重建 DB 或改业务数据。
旧元数据备份不得被重试覆盖；迁移中断恢复后两版本一致。读到未来版本沿用 NewerProject；读到 character 首版返回 mode:unsupported 且不改文件。
update_metadata 改名/触发词时不可把 mode 丢掉；相同值通过 runtime CAS 返回原版本。同版本迁移二次执行无写入，IO 失败保留原文件或可恢复标记。
依赖项目锁、atomic_json、既有迁移框架；最小测试 T01、T02、T06。不借模式迁移新增任何 project.db 表。

## 3 提示词库分类与 Formatter

### 3.1 分类模块

`PromptDictionary.category: str = 'full_content'`，显示「完整内容提示词」；分类放在提示词字典级，PromptEntry 仍为 tags/NL/aspect/rating，FeatureDictionary 仍按维度组织。
`load_dictionary(id: str, *, root: Path | None = None) -> PromptDictionary | FeatureDictionary` 兼容缺 category 的旧文件；写接口沿用 expected_revision/request_key。
字典 schema_version 升到 2，解码兼容 1/2；旧版缺字段补 full_content，新写显式 category；其它值预留但返回 dictionary:category_unsupported，不实现混合类别抽样。
`list_dictionaries(*, category: str | None = None, root: Path | None = None, kind: str | None = None) -> tuple[PromptDictionary | FeatureDictionary, ...]`；category 与 features 组合拒绝。
修改 _encode/_decode 白名单与 DTO 校验；保留 _operations、revision CAS、原子写入，category 计入请求摘要。旧 request_key 原记录优先返回，不能因升级自动重写其历史摘要。
依赖 dictionaries.py 原子存储和 validation；错误不落盘。相同 key/同请求返回原结果，不同请求 409；最小测试 T07、T08。

### 3.2 Formatter 插件合同与调用点

新增 prompts/formatters.py，仅注册恒等插件；模板替换插件接口预留，不实现角色字典、角色推断或任意表达式执行。
`FormatContext = {profile: ProfileSnapshot, values: Mapping[str, str], source_revision: str}`；values 预留 character_name、appearance、nl_description。
`FormatResult = {entry: PromptEntry, formatter_id: str, formatter_version: str, input_digest: str, output_digest: str}`。
`class Formatter(Protocol): id: str; version: str; def format(self, entry: PromptEntry, context: FormatContext) -> FormatResult: ...`
`apply_formatter(entry: PromptEntry, *, formatter: Formatter, context: FormatContext) -> FormatResult`：纯函数、无网络/DB/随机副作用；插件错误包装 formatter:failed，缺变量报 formatter:missing_variable。
调用顺序：抽取字典条目/完成可选 R1 精修 → Formatter → profile 内容/评级/序列化校验 → freeze_entries → 生成请求冻结 → mark_sent → 提交。
TaskService 在冻结候选为 seeds 前调用；SourceRunner 对外部导入、手工输入等绕开生产任务的入口在构造冻结请求前调用同一服务，检查格式化摘要避免二次处理。
只替换内容 tags/NL 中白名单占位符，不替换系统模板或 style_prompt；替换后重新分词规范化，未解析占位符禁止提交；变量值中的占位符不递归展开。
恒等插件遇含占位符内容返回 formatter:unavailable；未来插件依次精确替换 `{{character_name}}`、`{{appearance}}`、`{{nl_description}}`，输出长度与原内容校验使用同一限制。
重试使用冻结的 FormatResult 与变量快照，不按变化后的角色资料重新渲染；同原条目/上下文/插件版本确定性，不承诺对输出反复调用幂等。
依赖 PromptEntry、profile、内容与评级校验、既有 seeds 快照；最小测试 T09–T11。产品级提示词任务默认显式 style 上下文，绑定项目时冻结 project profile。

## 4 F26 任务注册表

### 4.1 类型、所有权与模块合同

新增 runtime/tasks.py：聚合已有领域状态，领域 runner/store 是唯一写入者；不做第二套执行队列，不新增 project.db 表，不通过列表查询启动任务。
`TaskKind = Literal['source','job','prompt','export','cleanup','model_download']`；WD/LLM 用 job 的 executor 关联资源区分。
`TaskState = Literal['pending','running','canceling','paused','done','failed','canceled']`；canceling 是聚合视图暂态，不新增数据库枚举。
`TaskDTO = {task_id: str, kind: TaskKind, project: ProjectRef | None, status: TaskState, progress: ProgressDTO, cancelable: bool, resources: tuple[ResourceRef, ...], version: str, reason_code: str | None, recovery: RecoveryDTO}`。
`ProjectRef = {project_id: str, display_name: str}`；`ResourceRef = {kind: str, id: str}`；不返回绝对路径、prompt、token、端点 URL 或完整结果。
`ProgressDTO = {completed: int, total: int | None, unit: Literal['items','images','files','bytes'], failed: int, skipped: int}`；completed 为已结算总数，含 failed/skipped，成功数由减法得出。
`RecoveryDTO = {resumable: bool, reconciliation_required: bool, unknown_count: int, action: Literal['none','resume_resource','reconcile_resource','restart_remaining']}`；可恢复不等于自动重发。
`TaskAdapter(Protocol)`：`async snapshot(resource_id: str) -> TaskDTO`；`async stop(resource_id: str, request: StopRequest) -> StopReceipt`；`async wait(resource_id: str) -> None`。
`TaskRegistry.register(adapter: TaskAdapter, resource: ResourceRef, project: ProjectRef | None) -> str`；`async list(query: TaskQuery) -> TaskPage`；`async get(task_id: str) -> TaskDTO`；`async cancel(task_id: str, request_key: str) -> StopReceipt`。
TaskQuery 含 kind/status/project_id 可选过滤及 limit=50（1–200）、cursor；TaskPage 含 items、next_cursor、event_cursor。分页冻结成员列表，有效期 60 秒，失效报 task:cursor_expired。
task_id 由进程实例、项目打开 generation（全局任务用 global）、kind、原始资源 id 生成不透明 ID；同资源重复注册得到同 ID，关闭重开不复用旧 project_id。
领域重试/恢复沿用原资源 ID；另开独立领域任务才产生新 ID。supervisor operation 若包装同一领域资源，仅注册别名，不在托盘显示两个任务。
重启先按现有 source/job、提示词 TaskStore、导出等可枚举持久资源重建视图；已关闭项目不后台打开扫描；内存 operation 不伪造持久历史，跨重启能力见 Q02。
terminal 内存记录默认保留 10 分钟、最多 1000 条；只驱逐终态且实际 worker 已退出者，活动/暂停任务不按 TTL 驱逐。过期 ID 返回 410 task:expired。
适配器映射：source→SourceRunner；job→JobRunner；prompt→TaskService；export/cleanup/model_download→对应领域取消句柄与 supervisor。没有协作停止句柄时 cancelable=false。
依赖现有 repositories、TaskStore、TaskSupervisor、EventBridge；资源快照读取失败不伪造 failed，API 返回 task:unavailable 并允许刷新；详情与取消未知 ID 为 404。
幂等：register 去重；列表只读；重复取消复用首个 StopReceipt；相同 key 用于不同 task 报 409；终态取消 200 no-op。最小测试 T12–T15。

### 4.2 API 与 SSE

| 路径 | 请求 | 响应与错误 |
|---|---|---|
| GET /api/tasks | TaskQuery 查询参数 | 200 TaskPage；422 非法过滤；410 游标过期 |
| GET /api/tasks/{task_id} | 无 | 200 TaskDTO；404 未知；410 已过期 |
| POST /api/tasks/{task_id}/cancel | `{request_key: str}` | 202 StopReceipt；终态/已完成停止 200；409 task:not_cancelable |
| GET /api/events?topics=task | Last-Event-ID 可选 | 复用现有 SSE 通道、鉴权与连接限制，不另开任务专用连接 |

`StopReceipt = {task_id: str, status: TaskState, accepted: bool, no_op: bool, version: str}`；202 只证明停止请求已受理，真正停止由详情/SSE 确认。
取消先读取领域最新状态并在控制锁内执行，不靠过时 DTO 决定；领域 CAS 冲突重新读取，已终态按 no-op 返回，其余 409 task:state_conflict。
SSE 类型：task.created、task.updated、task.progress、task.finished、task.removed；payload 仅 TaskDTO 摘要，移除事件含 task_id/version。
复用 EventBridge 的 epoch:sequence、资源 `{kind:'task', id:task_id}`、project_id；DTO version 在每次可见变化时单调递增，不采用 supervisor 当前固定 0/1/2 版本。
progress 继续最多每任务每 250ms 一条；created、状态变化和 finished 不节流，finished 带最终进度；先完成领域提交、再更新 registry、最后发布事件。
前端先连接 SSE 并缓存事件，再取 TaskPage，以 event_cursor 为分界合并；按 task_id/version 去重，翻页快照过期重拉。
遇 stream.resync_required、epoch 变化或队列溢出，清理旧分页并重取列表；任务进度不必精确回放每一步，终态必须可从详情恢复。
托盘展示全局任务与当前项目任务，项目关闭后活动停止过程仍可见；以关联资源跳转现有页面，paused 提供领域恢复入口，本版统一 API 不新增 resume。
前端拟新增 TaskTray 与 taskStore：负责展示/失效刷新/取消按钮状态，依赖 TaskDTO/SSE；错误按 code 显示，重连幂等，不自行推算成功。最小测试 T16、T17。

## 5 取消/关闭统一路径

### 5.1 控制合同

新增 runtime/cancellation.py；`StopReason = Literal['user','project_close','shutdown']`；`StopRequest = {reason: StopReason, deadline_monotonic: float, request_key: str}`。
`StopCoordinator.stop(task_id: str, request: StopRequest) -> Awaitable[StopReceipt]`；`drain(project_id: str | None, reason: StopReason) -> Awaitable[None]`。
用户取消、项目关闭、程序强制关闭按钮都调用同一 stop 流程；reason 只影响文案/诊断，不改变已提交结果与未知结果规则。操作系统 kill 无法保证执行清理，依赖恢复日志。
顺序：关闭接受/派发闸门 → 持久化可恢复的停止意图/paused 边界 → 通知适配器停止 → 等待在途至 deadline → 放弃远程等待并封存未知结果 → 等待本地文件/DB worker → 发布终态。
推荐等待 deadline=30 秒；超时后网络调用可中断，但已经 mark_sent 的外部调用记 unknown，不自动重发；纯本地线程不能安全杀死，继续显示 canceling 直至安全退出。
“已提交”指完成领域原子提交的结果，不仅是 HTTP 已发送：提交前后以领域事务/控制锁线性化；已经提交的 annotations、字典条目、导出成品、删除结果一律保留。
等待期间允许已有在途调用正常结算；deadline 后旧 generation 的晚到结果不覆盖新状态，按既有回执机制供核对；不把 unknown 映射成可重试失败。
首版推荐停止后底层保持 paused，视图显示 paused + user/shutdown 原因；canceled 留给既有不可恢复终态。停止确认前显示 canceling，具体兼容调整见 C36/Q01。
恢复仅派发明确 not_sent/pending 工作；远程 unknown 必须核对或显式放弃该项；本地纯推理未提交可重算，文件工作按已发布结果/检查点继续。
Runtime.close 仍单飞并 shield；先全局 draining，再向所有任务发 stop，随后 join、等 project leases、清空 writer、释放项目锁，最后关闭产品存储/线程池。
停止通知须覆盖所有任务后再并行等待，不能第一个阻塞任务阻止其它任务收到取消；不能先关闭 DB，再等持有写入权限的 worker。
无 project.db 新表：source/job 复用现有状态、进度 JSON/回执；prompt 复用 TaskStore；其余优先已有领域检查点，缺失持久支持必须暴露 recovery=false，见 Q02。
错误：停止写入失败保持 canceling/task:stop_persist_failed，不返回已安全关闭；重复 stop 复用同一控制 future，deadline 只能提前不能延长。最小测试 T18–T22。

### 5.2 逐类当前差距与落地要求

| 类别 | 当前实现是否满足（依据） | 差距与统一适配要求 |
|---|---|---|

## 6 资源控制器

### 6.1 LLM 网络资源模块

新增 resources/network.py；职责是每次实际发送的全局/端点/令牌容量与冷却，不接管业务重试、结果提交或模式路由。
`NetworkPolicy = {global_limit: int, endpoint_default: int, token_default: int, endpoint_limits: Mapping[str,int], token_limits: Mapping[str,int], backoff_base_s: float, backoff_cap_s: float}`。
默认 global=2、每端点=2、每令牌=1、退避基数=1s、指数上限=60s；Retry-After 超过上限仍尊重服务端时间，但超过请求总 deadline 则结束，不提前发送。
`async acquire(endpoint_id: str, token_refs: tuple[str,...], *, cancel: CancelToken, deadline: float) -> NetworkLease`；lease 提供 token_ref、`async release() -> None`，支持 async context manager。
`cooldown(endpoint_id: str, token_ref: str, *, retry_after_s: float, attempt: int) -> None`；`configure(policy: NetworkPolicy) -> int` 返回配置 revision。
同一调度锁内选择可用令牌并同时预留三层容量；不逐个持有 semaphore 等下一层，不在全令牌冷却时占全局槽。按任务公平排队，令牌使用现有轮询次序。
冷却为 max(Retry-After, min(60, 2**attempt)+受控抖动)，时钟/随机源可注入；429 先释放本次 lease，再冷却并轮换；明确端点级限流时同时阻塞端点。
令牌容量按 secret 引用身份跨端点计数；token 明文只在实际发送前由 SecretStore 解析。若多个引用指向同一密钥，需统一引用配置，不能靠日志暴露明文去重。
LlmService.complete 删除逻辑请求级 _gate 持有，每个 adapter.complete 前 acquire；_select_token/_cursor/_cooldowns 合并进控制器，保留 _active 的重复 request_id 防护。
complete_json 修复、视觉降档与 probe_models 均经过同一控制器；既有发送次数/总 deadline 预算不因换 token 或重新排队重置。unknown 在取消路径禁止业务层重放。
executors/runner 只保留每 job 的在途公平窗口；prompts/tasks 的 _gate 可保留业务任务限制，不算网络并发，不能与服务争用同一个 lease。
等待可取消，取消返回 not_sent；发送后中断返回 unknown；容量耗尽等待至 deadline 报 resource:timeout；策略非法报 resource:invalid_policy，配置更新不撤销在途 lease。
依赖 LlmService、SecretStore、CancelToken 与单调时钟；release 重复调用无副作用，重复 acquire 同 request attempt 拒绝而不多占槽；最小测试 T23–T26。

### 6.2 本地算力与设置

新增 resources/compute.py；`ComputePolicy = {gpu_slots: int, cpu_slots: int, gpu_budget_bytes: int | None, reserve_bytes: int, reserve_ratio: float, wd_max_batch: int}`。
默认每 GPU 槽位=1、CPU 推理槽位=1、显存预算自动、reserve_bytes=1GiB、reserve_ratio=0.2、WD batch 上限=4；CPU 线程池大小不等于推理并发，ORT 内部线程另行约束。
自动显存上限=max(0,total-max(1GiB,total*0.2))；当前准入同时满足“已登记驻留+在途预留+新估算≤上限”和“新分配≤当前 free-安全余量”，不把已驻留模型重复扣两遍。
`ComputeDemand = {owner: str, device_id: str, backend: str, model_key: str, resident_bytes: int, workspace_bytes: int, requested_batch: int}`。
`async acquire(demand: ComputeDemand, *, cancel: CancelToken, deadline: float) -> ComputeLease`；lease 返回 provider/actual_batch/reserved_bytes，并在真实 worker 退出后 release。
`register_resident(model_key: str, device_id: str, bytes: int) -> None`；`release_resident(model_key: str, device_id: str) -> None` 必须在实际卸载后调用；同模型引用计数避免重复预算。
WD 的 plan_batch 改为基于 lease 可用预算规划，受动态 batch 能力约束；缺显存/模型内存估算沿用 CPU batch=1 的保守路径，不凭未知预算开 GPU。
WdExecutor.predict 的 _worker 可保留会话线程安全保护，但跨实例共享 ComputeController；_sessions 长驻内存登记驻留预算，GPU 推理槽释放不等于卸载模型。
OOM 时 batch 减半并更新预留，仍失败则释放 GPU 资源后另申请 CPU 槽；CPU fallback 也不能绕过控制器，取消后不再 fallback。
JobRunner 当前 execute 每次传单图，因此配置 batch>1 不代表 jobs 已实现批推理；首版共享资源控制先支持此路径，跨图片批调度另见 Q04。
未来本地 VLM/YOLO 实现同一 ComputeDemand/lease，不另建 GPU 锁；模型下载只使用 IO/下载资源，不抢推理槽；本版不启用这些未来执行器。
产品设置存产品配置，不进 project.json：拟议 GET/PUT /api/settings/resources，DTO `{revision: str, network: NetworkPolicy, compute: ComputePolicy}`，PUT 带 expected_revision，409 冲突。
设置范围：各并发上限为正整数，比例 0≤r<1、字节预算正数或 null；减少上限只阻止新准入，不能强杀在途。重启加载配置，更新原子写入后生效并发布 settings.updated。
依赖 probe_device、模型 manifest、WD 与产品配置存储；预算不足排队，单项永不可能满足报 resource:insufficient；幂等释放/CAS 更新，不使用虚假空闲显存保证不 OOM。最小测试 T27–T30。
